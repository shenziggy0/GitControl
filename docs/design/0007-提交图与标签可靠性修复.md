# 设计文档：提交图与标签可靠性修复

- 日期：2026-11-25
- 状态：草稿

## 1. 需求理解

- 分支筛选要随分支移动更新，即使所有分支和标签合起来指向的提交集合保持相同。
- 单个标签对象缺失时，工作台仍显示分支、工作区改动和可用标签。侧栏要能区分损坏标签与指向文件或目录的有效标签。
- 大量标签仍可加载和定位提交。Git 参数长度上限不应限制提交起点的数量。
- 同一提交关联多个引用时，提交图保留简短预览，完整名称通过同一行的按钮查看。
- 沿用当前 macOS 桌面工作台和每页 60 条的提交图。假设保留现有排序和标签定位入口，无待确认事项。

## 2. 接口改动

| Tauri IPC | 入参 | 出参与行为 | 错误与兼容性 |
| --- | --- | --- | --- |
| `repo_status` | `projectId` | 复用 `Status.tags`。每个标签可标为不可用，整批读取失败时通过 `tags_error` 显示标签区错误。 | 仓库状态仍使用现有字符串错误。标签失败通过新增可选字段回报，旧字段含义保留。 |
| `repo_history` | `projectId`、`tips` | 继续返回拓扑和日期排序的提交列表。校验、去重后的完整对象 ID 通过 Git 标准输入传递。 | 保留无效对象 ID、Git 失败和超时的字符串错误。前端调用方式无改动。 |

在 `src-tauri/src/git.rs` 中用 `for-each-ref` 枚举名称和原始对象 ID，再用 `cat-file --batch-check` 批量解析最终目标。Git 为缺失对象逐行返回结果，可保留正常标签。历史与标签检查共用现有 Git 子进程超时和输出处理，通过临时文件提供标准输入，避免参数长度及管道互等。

在 `src/ui/main.js` 复用同一个筛选分支目标供历史筛选和图布局缓存使用。目标或提交数据改变后，在 `src/ui/graph.js` 按当前结果校正页码。每行最多预览两个引用，额外引用通过独立按钮打开完整列表。弹窗沿用工作台的原生 `dialog` 样式。

## 3. 数据库改动

无。标签状态、筛选和分页均为临时数据，涉及只读 Git 操作。

## 4. 流程图

```mermaid
flowchart TD
    refresh["刷新仓库"] --> status["读取分支和工作区状态"]
    status --> refs["枚举标签并逐项解析目标"]
    refs --> sidebar["显示有效标签及读取异常"]
    refs --> tips["合并有效标签和分支的提交 ID"]
    tips --> history["通过标准输入加载 Git 历史"]
    status --> scope["更新所选分支的目标提交"]
    history --> graph["按筛选范围重算布局和页码"]
    scope --> graph
    graph --> overflow["点击另有 N 个查看完整引用"]
```

## 5. 范围边界

- 本次涉及标签读取和提示、提交历史输入、图布局缓存与分页、提交行的引用列表。
- 范围限于工作台提交图。提交、推送、远端核对和仓库修复沿用原有入口。
- 实施前同时核对仓库文档和代码，以实际调用链为准。优先复用现有接口、数据模型、Git 执行器和弹窗样式。新增字段及样式只服务上述行为，测试限于关键路径和这四个回归场景。

## 6. 验收标准

- [ ] 筛选 `topic` 后把它从第一条提交移动到第二条，标签仍保留第一条。无需切换筛选，计数和图都显示两条。移回一页内后，页码退出已不存在的第二页。
- [ ] 在临时仓库移除一个附注标签对象。分支、改动、其余标签及提交图仍可读取，缺失标签有独立提示。轻量、附注、嵌套和非提交标签保持原有分类和定位行为。
- [ ] 用 28,000 个标签分别指向 28,000 条本地提交。通过现有历史入口返回完整历史，包含只能通过标签到达的提交。
- [ ] 同一提交添加 24 个标签，宽窗和窄窗都可通过鼠标或键盘打开完整列表，关闭后焦点回到触发按钮。点击提交行仍进入提交详情。

## 7. 影响面

后端涉及标签解析和提交历史读取，前端涉及侧栏提示、分支筛选、分页和图中引用展示。标签解析按批处理，收起标签区时延迟渲染列表。历史仍按原有顺序读取并分页展示。Git 子进程继续使用既有超时和只读参数。

## 8. 回滚方案

若仓库状态、历史排序或提交详情入口出现回归，可只回退本 RFC 对应的代码和测试，保留工作区其他改动。没有数据迁移或持久状态需要回滚。
