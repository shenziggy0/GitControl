# GitControl · macOS 首版设计

## 使用目标

用户在几个本地 Git 仓库之间轮流工作。打开应用或点回项目时，直接看到所在分支、改动文件和待推送提交。需要理解改动时展开 Claude 聊天，需要自己操作时展开终端。

## 窗口与切换

- 左栏提供「添加项目」，通过 macOS 文件夹选择器添加已有 Git 工作区，用目录区分同名项目。建议在项目名旁显示最近读到的分支名，切回项目时刷新。项目列表保存在本机。首次打开且没有项目时显示添加入口。
- 三栏全部展开时各占约三分之一。中栏上方是内置聊天，下方是交互终端，两者可独立收起。只展开一个时，它使用中栏全部高度。
- 每次启动，两块面板都收起，状态区使用中栏和右栏的空间，保留聊天与终端的展开按钮。建议启动时自动选中上次查看的项目。
- 同次运行中，每个项目保留自己的面板展开状态、聊天记录、终端进程、输出和未发送的输入。切项目只改变可见内容。后台到达的 Claude 回复归入发起问题的项目。退出再启动时恢复项目列表与选择，聊天和终端从新会话开始。

## 仓库状态

- 顶部显示当前分支与相对跟踪分支的待推送提交数。计数基于本机最近一次取得的远端信息。未关联上游、尚无提交、未处于命名分支时分别显示具体状态。读取失败时显示原因。
- 文件按已暂存、未暂存和未跟踪展示，标出删除、重命名和冲突。同一文件同时有已暂存和未暂存内容时，两组各列一次。没有改动时显示「工作区干净」。
- 选中项目后重新读取状态。项目可见期间，编辑器改文件、终端切分支或 Claude 完成提交后也应自动更新。快速切换项目时，只接收属于当前项目的状态结果。

## Claude 聊天与提交

- 使用内置消息界面连接本机 Claude Code，每个项目独立建立对话，工作目录绑定到发起消息时选中的工作区。首次展开并使用聊天时才需要 Claude 可用。Claude 未安装或未登录时，在聊天区提示处理方式，其他区域仍可用。
- 问项目或状态时，Claude 可以读取项目文件、Git 状态与差异来回答。诸如「为什么改了这些文件」「这些可以提交吗」属于问答，不能触发暂存或提交。读写工具的权限要与本次请求匹配。
- 用户明确说「提交」且范围清楚时，直接在该工作区执行，提交说明用中文。范围按用户点名的文件、选中的文件或明确指代的改动决定。如果范围会影响是否夹带其他改动且无法判断，先问清文件范围。已有的无关暂存内容也应保留。
- 建议按选中行理解「提交选中的改动」。例如同一文件同时出现在两组，只选「已暂存」那行时，仅提交暂存版本，保留后续编辑。其他选区若依赖未选中的内容且无法单独提交，说明原因并询问范围。
- 提交成功后显示分支、短提交号与提交说明，并刷新状态。提交失败时显示实际原因。提交与推送是两项独立操作，本次提交的授权仅覆盖本地提交。
- 聊天显示进行中、完成、失败状态，允许停止当前回答。收起面板与停止回答是两个独立动作。

## 终端

每个项目首次展开终端时，在对应工作区启动本机交互式 shell，支持输入、持续输出和中断。收起或切项目时保持同一个进程，展开时恢复原来的内容。终端自行切换目录仅影响该终端，右栏始终展示左栏选中的项目。

## 方案选择与实施取舍

讨论过三种方式。直接嵌入 Claude CLI 开发量小，界面跟随 CLI。增加「问 Claude」快捷操作能省去输入文件名。用户选择内置聊天界面，应用负责消息显示和面板收放，并可将选中的文件放进提问上下文。首版建议以本机 Git 获取状态，以真实终端进程运行 shell。桌面框架、Claude Code 接入方式、变化监听策略交给实施阶段，先验证真实 CLI 的问答、工具权限和提交行为。

## 首版验收

1. 添加两个真实仓库，退出再启动后两个面板默认收起，选中项目的状态立即可见。
2. 使用包含已暂存、未暂存和未跟踪文件的仓库，逐项对照实际 Git 输出。在外部编辑文件后，界面自行更新。
3. 在 A 项目开始 Claude 问答，终端输入半条命令，切到 B 再切回 A。回答和未发送的输入都留在 A，B 的状态独立。
4. 使用真实 Claude 会话询问「这些改动可以提交吗」，验证回复后工作区、暂存区与分支指针均未改变。
5. 在专用真实测试仓库明确要求提交指定改动，并在执行期间切换项目。核对提交归属、提交范围、中文说明，验证 B 仓库和远端引用均未改变。
6. 无上游分支、干净工作区及 Claude 不可用时分别验证对应提示。
